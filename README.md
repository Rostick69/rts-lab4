Практическая работа №4 по дисциплине «Системы реального времени».

Консольное приложение на Python моделирует передачу сообщений по общей шине. Для каждого сообщения оно показывает, сколько времени занимает передача, как меняется задержка из-за очереди и успевает ли получатель обработать сообщение к заданному сроку.

**Вариант 2 — промышленная сеть контроллеров** (аварийный сигнал, команда привода, состояние линии и диагностика).

## Функциональные возможности

- Читает параметры канала и сообщения из CSV. Модели `Channel` и `Message` описаны через `@dataclass`.
- Рассчитывает **время передачи** и **базовую задержку** при свободном канале.
- Моделирует **приоритетный арбитраж**. Когда шина освобождается, первым начинает передачу ожидающее сообщение с наименьшим номером приоритета.
- Находит **максимальную задержку** и **джиттер** каждого потока за гиперпериод.
- Проверяет дедлайны и выводит список потоков, в которых хотя бы одно сообщение опоздало.

---

## Краткие теоретические сведения

| Величина | Как считается |
|---|---|
| Время передачи, мс | `C = 1000 · L / V`, где L — размер сообщения в битах, V — скорость в бит/с |
| Базовая задержка | Время передачи + задержка распространения + время обработки |
| Задержка при арбитраже | Ожидание свободной шины + базовая задержка |
| Джиттер потока | Максимальная задержка минус минимальная для сообщений одного потока |
| Проверка дедлайна | Максимальная задержка ≤ дедлайн |
| Гиперпериод | Наименьшее общее кратное периодов всех потоков |

Все потоки начинают работу в момент 0. Начатый кадр передаётся целиком. Поэтому даже аварийный сигнал с высшим приоритетом может ждать, пока шина закончит передачу другого кадра.

## Входные данные

В [channel.csv](data/channel.csv) заданы скорость **500 000 бит/с**, задержка распространения **0,1 мс** и время обработки **0,2 мс**. Параметры четырёх потоков лежат в [variant2.csv](data/variant2.csv).

```csv
name,priority,bits,period_ms,deadline_ms
Аварийный сигнал,1,500,5,3
Команда привода,2,1000,10,5
Состояние линии,3,2000,20,8
Диагностика,4,2500,50,10
```

| Поле | Значение |
|---|---|
| `name` | Название сообщения |
| `priority` | Приоритет потока, 1 — высший |
| `bits` | Длина одного сообщения в битах |
| `period_ms` | Интервал между выпусками сообщений, мс |
| `deadline_ms` | Допустимое время от выпуска до завершения обработки, мс |

## Пример работы

```text
Набор: variant2.csv. Скорость: 500000 бит/с.
Все значения времени указаны в мс. Приоритет 1 — высший.
Сообщение        | Пр. | Бит  | Передача | Базовая | Максимум | Джиттер | Дедлайн | Успело
Аварийный сигнал | 1   | 500  | 1.00     | 1.30    | 4.30     | 3.00    | 3.00    | нет
Команда привода  | 2   | 1000 | 2.00     | 2.30    | 6.30     | 3.00    | 5.00    | нет
Состояние линии  | 3   | 2000 | 4.00     | 4.30    | 7.30     | 0.00    | 8.00    | да
Диагностика      | 4   | 2500 | 5.00     | 5.30    | 13.30    | 5.00    | 10.00   | нет
Дедлайн превышен: Аварийный сигнал, Команда привода, Диагностика
```

За гиперпериод **100 мс** шина занята на **70 %**. Только поток «Состояние линии» укладывается в срок при каждом выпуске. Его максимальная задержка — **7,3 мс** при дедлайне **8 мс**. Для диагностики при свободной шине хватило бы **5,3 мс**, но с учётом очереди задержка достигает **13,3 мс** при дедлайне **10 мс**.

## Проверка на контрольном примере

Набор из методички хранится в [example.csv](data/example.csv). Для проверки дедлайны приняты равными периодам.

```console
python src/main.py data/example.csv
```

```text
Набор: example.csv. Скорость: 500000 бит/с.
Все значения времени указаны в мс. Приоритет 1 — высший.
Сообщение | Пр. | Бит  | Передача | Базовая | Максимум | Джиттер | Дедлайн | Успело
M1        | 1   | 1000 | 2.00     | 2.30    | 6.30     | 4.00    | 10.00   | да
M2        | 2   | 2000 | 4.00     | 4.30    | 6.30     | 0.00    | 20.00   | да
M3        | 3   | 4000 | 8.00     | 8.30    | 14.30    | 4.00    | 50.00   | да
Все сообщения укладываются в дедлайн.
```

Времена передачи **2, 4 и 8 мс** совпадают с примером из задания. При одновременном выпуске M3 ждёт, пока пройдут M1 и M2. Его доставка занимает **2 + 4 + 8 + 0,1 + 0,2 = 14,3 мс**.

## Сборка и запуск

Для работы по методичке нужен Python 3.10 или новее. Все модули входят в стандартную библиотеку Python.

**В Visual Studio** откройте `rts-lab4.sln` с установленным компонентом «Разработка на Python» и нажмите **Ctrl+F5**. По умолчанию запустится вариант 2. Для примера из методички укажите `data/example.csv` в **Project → Properties → Debug → Script Arguments**.

**В терминале** выполните нужную команду из корня проекта.

```bash
python src/main.py                            # вариант 2
python src/main.py data/example.csv           # контрольный пример
python -m unittest discover -s tests -v       # четыре автоматические проверки
```

Другой файл параметров канала можно передать через `--channel путь.csv`.
